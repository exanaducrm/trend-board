# 인기 보드

네이버, 11번가, G마켓, 옥션, 아이템스카우트의 인기검색어와 인기상품을 한 화면에서 봅니다.

## 파일 버전 확인

`server.py`, `collectors.py`, `dashboard.html` 에는 같은 빌드 번호가 박혀 있습니다.
하나라도 옛날 것이 섞이면 화면 맨 위에 경고가 뜹니다.
검은 창 첫 줄과 브라우저 탭 제목에서도 확인할 수 있습니다.

세 파일은 항상 같이 교체하세요.

빌드가 바뀌면 저장해 둔 수집 일정을 버리고 즉시 다시 받습니다.
"다음 수집은 6시간 뒤"가 남아서 고친 코드가 반영되지 않는 일을 막기 위한 것입니다.

## 빠른 시작

파일을 한 폴더에 모아두고 **`run.bat`을 더블클릭**하면 됩니다.
처음 한 번은 패키지를 설치하느라 1~2분 걸리고, 그다음부터는 바로 뜹니다.
잠시 뒤 브라우저가 저절로 열립니다. 안 열리면 http://127.0.0.1:8787 로 들어가세요.

검은 창은 서버입니다. 닫으면 보드도 꺼집니다.

| 파일 | 하는 일 |
|---|---|
| `run.bat` | 보드 실행. 평소에는 이것만 쓰면 됩니다 |
| `check.bat` | 페이지에 어떤 링크가 있는지 분석 (항목이 안 뽑힐 때) |
| `demo.bat` | 예시 데이터로 화면만 확인 (쇼핑몰에 접속하지 않음) |
| `curl.bat` | 개발자도구에서 복사한 요청으로 수집기 설정 자동 생성 |
| `share.bat` | 같은 네트워크의 다른 PC에서도 볼 수 있게 실행 |
| `preview.bat` | 깃허브 페이지에 올렸을 때의 모습 미리 보기 |

**파이썬도 자동으로 설치합니다.** 없으면 `run.bat` 이 먼저 물어봅니다.
Y를 누르면 winget 이나 python.org 에서 내려받아 이 사용자 계정에만 설치합니다.
관리자 권한은 필요 없고 1~2분 걸립니다. N을 누르면 다운로드 페이지를 열어 줍니다.

직접 설치하실 때는 설치 화면 맨 아래 **Add python.exe to PATH** 를 체크하세요.

명령 프롬프트에서 직접 띄우려면,

```
cd 폴더경로
pip install -r requirements.txt
python server.py
```

## 왜 파이썬이 필요한가

브라우저는 스크립트가 다른 도메인의 응답을 읽지 못하게 막습니다(CORS).
네이버도 G마켓도 외부에서 읽어도 좋다는 허가를 주지 않기 때문에,
HTML 파일을 더블클릭하는 방식으로는 만들 수 없습니다.

```
브라우저 ──▶ 로컬 서버 (같은 주소라 제한 없음)
로컬 서버 ──▶ 쇼핑몰 (브라우저가 아니라 CORS 자체가 없음)
```

수집은 파이썬이 하고, 화면은 그 서버만 바라봅니다.

## 갱신 방식

화면은 5초마다 서버 상태를 확인해 다시 그립니다. 같은 컴퓨터 안이라 부담이 없고,
수집이 끝나는 즉시 결과가 뜹니다. 쇼핑몰을 두드리는 것과는 상관없습니다.

쇼핑몰 재수집 주기는 소스마다 다릅니다.
고른 값은 브라우저에 저장되어 다음에 열어도 유지됩니다.
다음 갱신까지 남은 시간이 옆에 초 단위로 표시됩니다.

직접 갱신하는 방법은 세 가지입니다.

- 각 패널의 **다시 받기**: 그 소스 하나만 즉시 다시 수집

수동 갱신을 하면 자동 타이머도 그 시점부터 다시 셉니다.

자동 갱신은 수집할 때가 된 소스만 다시 받습니다. 소스별 주기는
데이터가 실제로 바뀌는 속도에 맞춰 다르게 잡아 두었습니다.
**지금 새로고침**은 주기를 무시하고 강제로 다시 받습니다.

| 소스 | 기본 수집 주기 |
|---|---|
| 네이버 데이터랩 인기 검색어 | 6시간 (하루 단위 집계입니다) |
| 네이버 데이터랩 인기분야 | 6시간 |
| 네이버쇼핑 BEST | 15분 |
| 11번가 베스트 | 15분 |
| 옥션 베스트 | 15분 |

주기는 `collectors.py`의 각 소스 `interval` 값(초)으로 조정하세요.

## 받아오는 개수

쇼핑몰 베스트(네이버쇼핑, 11번가, 옥션)는 **50개**, 그 외는 **30개**까지 받습니다.
`collectors.py` 맨 위의 두 값으로 조정합니다.

```python
DEFAULT_LIMIT = 30
PRODUCT_LIMIT = 50
```

이 값을 바꾸면 전체에 적용되고, 특정 소스만 다르게 하려면 그 수집기에 `limit=` 을 따로 주면 됩니다.

네이버 데이터랩만 구조가 다릅니다. 10개 분야를 카테고리 탭으로 나눠 보여주기 때문에
분야마다 10개씩입니다. 한 탭에 더 깊게 보고 싶으면 `per_category` 값을 올리세요.

받아온 목록은 `state.json`에 저장됩니다. 서버를 껐다 켜도 화면이 비지 않고
순위 변동(▲ ▼ 신규) 비교 기준도 유지됩니다. 처음부터 다시 받으려면
`python server.py --reset` 을 한 번 실행하세요.

## 데이터랩이 쓰는 API

분야별 인기 검색어는 페이지가 쓰는 API를 그대로 부릅니다.

```
https://datalab.naver.com/shoppingInsight/getKeywordRank.naver?timeUnit=date&cid=50000000
```

`timeUnit` 은 date / week / month, `cid` 는 분야 코드입니다.
이 주소가 막히면 구간을 직접 넘기는 예전 API(`getCategoryKeywordRank.naver`)로 한 번 더 시도합니다.

인기분야도 짝이 되는 주소(`getCategoryRank.naver`)를 먼저 두드려 보고,
안 되면 페이지 HTML을 읽는 쪽으로 물러섭니다. 이 주소는 확인된 것이 아니라 추측입니다.
`--preview naver_section` 의 "고른 배열" 줄을 보면 어느 쪽으로 읽었는지 알 수 있습니다.

## 집계 기간 선택

네이버 데이터랩 두 패널에는 **일간 / 주간 / 월간** 버튼이 붙어 있습니다.
누르면 그 자리에서 다시 수집합니다.
서버를 껐다 켜면 항상 **일간**으로 돌아옵니다. 고른 값은 저장하지 않습니다.

주간은 최근 7일, 월간은 최근 30일 구간을 한 번에 요청합니다.

## 분야를 한 화면에 펼쳐 보기

분야별 인기 검색어는 11개 분야를 가로로 나란히 펼칩니다.
면세점은 응답이 비어 있어 목록에서 뺐습니다. 필요하면 `NAVER_CIDS` 에 다시 넣으세요.
요청 사이에 0.8초 간격을 두므로 한 번 받는 데 10초 안팎 걸립니다.
인기분야도 같은 방식으로 11개 분야를 가로로 펼칩니다.
탭으로 보고 싶으면 `dashboard.html` 의 `SPREAD_GROUPS` 에서 그 키를 빼면 됩니다.

```js
const SPREAD_GROUPS = new Set(['naver_datalab_keyword', 'naver_section']);
```

## 화면 배치

데이터랩 두 소스가 각각 한 줄을 통째로 쓰고,
맨 아랫줄에 네이버쇼핑, 11번가, 옥션이 셋으로 나뉩니다.
순서를 바꾸려면 `dashboard.html` 위쪽의 `LAYOUT` 을 고치세요.

```js
const LAYOUT = [
  ['naver_datalab_keyword'],
  ['naver_section'],
  ['snx_best', 'elevenst_best', 'auction_best'],
];
```

여기 없는 소스를 추가하면 맨 아래 줄에 이어 붙습니다.
화면이 좁아지면 3칸이 2칸으로, 더 좁아지면 1칸으로 줄어듭니다.

그 목록을 실어오는 내부 요청을 찾아 붙여야 하는데, 사이트 개편마다 바뀌는 부분이라
코드에 박아두는 대신 설정만 채우면 되도록 만들어 뒀습니다.

## 엔드포인트 찾는 법

목록을 XHR로 따로 받아오는 사이트는 그 요청을 찾아야 합니다.
`curl.bat` 이 이 과정을 대신해 줍니다.

1. 해당 페이지를 크롬에서 엽니다.
2. F12 → **Network** → **Fetch/XHR** 로 거르고 새로고침합니다.
3. 응답(Response)에 상품 목록이 들어 있는 요청을 찾습니다. 이름에 `rank`, `best`, `list` 같은 말이 붙는 경우가 많습니다.
4. 그 요청을 우클릭 → **Copy** → **Copy as cURL (bash)**
5. 이 폴더에 `curl.txt` 로 저장하고 `curl.bat` 을 실행합니다.

그러면 요청을 그대로 보내보고, 응답에서 상품 목록 배열을 찾아
`collectors.py` 에 붙여넣을 설정을 통째로 만들어 줍니다.

```
    30개  data.bestList
         키    prdNo, prdNm, finalDscPrice

        JsonApiCollector(
            api_url="...",
            list_path="data.bestList",
            title_key="prdNm",
            id_key="prdNo",
            price_key="finalDscPrice",
            enabled=True,
        ),
```

`curl.txt` 에는 로그인 쿠키가 들어 있을 수 있으니 다른 곳에 공유하지 마세요.

수동으로 채우려면 `collectors.py`의 해당 항목을 고치고 서버를 다시 띄웁니다.

응답이 이렇게 생겼다면,

```json
{ "data": { "products": [ { "name": "무선 이어폰", "no": 12345, "price": 39000 } ] } }
```

설정은 이렇게 됩니다.

```python
JsonApiCollector(
    key="snx_best",
    label="네이버쇼핑 가장 많이 본 BEST",
    source_url="https://snxbest.naver.com/home",
    api_url="여기에 XHR 주소",
    list_path="data.products",
    title_key="name",
    id_key="no",
    url_template="https://shopping.naver.com/catalog/{id}",
    price_key="price",
    interval=900,
    enabled=True,          # 이 줄을 True 로
)
```

## 페이지가 나뉘는 API

한 번에 30개가 안 오는 API는 `api_url` 에 주소를 여러 개 주면 순서대로 이어 받습니다.
중복은 걸러지고, 30개가 차면 남은 주소는 부르지 않습니다.

```python
api_url=[
    "https://.../page?pageId=PCBEST",
    "https://.../page?pageId=PCBEST&pageMode=NEXT&pageNo=2",
],
```

한 쪽이 실패해도 나머지로 채우고, 몇 쪽이 빠졌는지 화면에 경고로 표시합니다.

## 결과가 사이트와 맞는지 확인하기

```
python server.py --preview elevenst_best
```

실제로 한 번 수집해서 순위표를 그대로 찍어 줍니다.
사이트 화면과 나란히 놓고 1위부터 맞는지 보면 됩니다.
어떤 배열을 골랐는지도 같이 나오므로, 순위가 어긋나면 그 경로를 `list_path` 에 지정해
고정할 수 있습니다.

```
고른 배열
  data.sections[1].products (18개, 점수 5)

순위   상품명                                    가격
1     롯데호텔월드 디럭스 객실 1박 패키지          250,000원
```

## 잘 안 될 때

**"자동 수집이 차단되었습니다"가 뜬다** — 사이트가 봇 확인 화면을 돌려준 경우입니다.
헤더나 요청 방식을 바꿔서 될 문제가 아니라, 사이트가 원치 않는다고 밝힌 것입니다.
자동 재시도는 멈추고 사이트 바로가기로 대체됩니다.

정식으로 데이터를 받는 경로를 찾는 편이 낫습니다.

- **네이버 검색광고 API**: 키워드와 월간 검색수를 목록으로 제공합니다. 순위표가 필요하면 이쪽입니다.
- **네이버 데이터랩 오픈API**: 지정한 키워드의 추이를 줍니다. 인기검색어 목록 자체는 아닙니다.
- **G마켓·옥션**: 같은 회사라 한 번에 문의하면 됩니다. 파트너 프로그램으로 상품 데이터를 받을 수 있는지 확인해 보세요.

**패널이 비어 있는데 오류도 없다** — 검은 창을 확인하세요.
`수집 시작`, `수집 완료`, `수집 실패` 로그가 소스마다 찍힙니다.
`수집 시작`만 있고 그 뒤가 없으면 아직 받아오는 중입니다.

**한글이 깨진다** — 옥션은 아직 EUC-KR입니다. 지정한 인코딩으로 읽었을 때
깨진 글자가 많으면 응답이 말하는 인코딩으로 알아서 되돌리므로 대부분 문제가 없습니다.
그래도 깨지면 해당 수집기의 `charset` 값을 고치세요.

**수집 실패 로그가 원인을 알려줍니다** — 항목을 못 뽑으면 검은 창에 이런 식으로 찍힙니다.

```
'goodsCode=([0-9]+)' 형태의 상품 링크를 찾지 못했습니다.
가장 많은 링크 형태: /DetailView.aspx?ItemNo,frm(30회)
```

이러면 `id_pattern` 을 `ItemNo=([0-9]+)` 로 바꾸면 됩니다.
심긴 JSON 쪽도 마찬가지로, 찾은 배열의 경로와 키 이름을 오류 메시지에 같이 적어 줍니다.

**페이지에 심긴 데이터 찾기** — 네이버쇼핑 BEST처럼 목록을 자바스크립트로 그리는 페이지도,
서버가 내려주는 HTML 안에 데이터를 통째로 심어두는 경우가 많습니다.
`EmbeddedJsonCollector` 가 그 덩어리를 꺼내 상품 목록으로 보이는 배열을 스스로 찾습니다.
`check.bat` 을 돌리면 어떤 배열이 몇 개짜리로 들어 있는지 경로와 키 이름까지 보여줍니다.
자동으로 못 고르면 그 경로를 `list_path` 에 넣으면 됩니다.

**페이지는 열리는데(HTTP 200) 항목을 하나도 못 뽑는다** — 링크 패턴이 안 맞는 경우입니다.
`check.bat` 을 돌리거나

```
python server.py --inspect auction_best
```

를 실행하면 그 페이지에 어떤 형태의 링크가 몇 개씩 들어 있는지 세어 줍니다.
같은 형태가 수십 개 나오는 줄이 상품 목록입니다. 거기 보이는 쿼리 이름을
`collectors.py` 의 `id_pattern` 에 맞추면 됩니다.

어떤 형태도 열 개를 넘지 않으면 목록을 자바스크립트로 그리는 구조라,
`JsonApiCollector` 방식으로 바꿔야 합니다.

## 링크 이동

- 상품은 상세 페이지로 바로 갑니다.
- 검색어는 원래 링크가 없어서 해당 몰의 검색 결과 주소를 만들어 붙였습니다.
- 전부 새 탭으로 열립니다.

```
demo.bat           예시 데이터로 화면 확인

collectors.py      사이트별 수집기
dashboard.html     화면
requirements.txt   필요한 패키지
```

실행하면 `state.json`(받아온 목록)이 자동으로 생깁니다. 지워도 되고, 지우면 다시 만들어집니다.

## 다른 사람도 보게 하기

사내망 공유와 깃허브 페이지 두 가지 방법이 있습니다. `DEPLOY.md` 를 보세요.
간단히는 `share.bat` 을 실행하면 같은 네트워크의 다른 PC에서 접속할 수 있습니다.

## 다른 PC로 옮길 때

폴더를 통째로 복사하고 `run.bat` 을 실행하면 됩니다.
파이썬이 없으면 물어본 뒤 설치하고, 패키지도 없으면 이어서 설치합니다.

예전 버전을 쓰셨다면 폴더에 `.installed` 라는 파일이 있을 수 있습니다.
지금은 쓰지 않으니 지우셔도 됩니다.
그 파일 때문에 설치를 건너뛰어 서버가 바로 종료되는 문제가 있었습니다.
